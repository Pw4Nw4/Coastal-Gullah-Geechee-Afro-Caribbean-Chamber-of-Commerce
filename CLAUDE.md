# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Marketing site for the Coastal Gullah Geechee & Afro-Caribbean Chamber of Commerce (Savannah, GA). Plain HTML/CSS/vanilla JS with no build step, served by a small dependency-free Node server (`server/`) that also handles Stripe checkout and form submissions. No package manager, linter or tests for the site itself; the one exception is `mascot/`, a separate React project for the chat's animated bird (its own `package.json`, built into `js/sankofa-mascot.js`). GitHub: `Pw4Nw4/Coastal-Gullah-Geechee-Afro-Caribbean-Chamber-of-Commerce` (public). Hosted on F09 Tech's Coolify with the `Dockerfile` build pack; the ops record lives in `D:\projects` (see that folder's `AGENTS.md`).

## Running

Dev server is defined in `.claude/launch.json` (name `site`): `node server/index.js --port=5173`, then open http://localhost:5173. It needs Node 20+ and nothing installed. Locally, submissions are saved to `data/` (git-ignored). Checkout returns "Payments are not configured yet" until `STRIPE_SECRET_KEY` is set. All settings are environment variables documented in `.env.example`.

The mascot demo is the `mascot` launch configuration (Vite on port 5174; run `npm install` in `mascot/` first).

The server only serves files matching its `PUBLIC` pattern (`*.html` at the root, `/css`, `/js`, `/images`). A new public folder or file type must be added there and to `TYPES`, or it 404s.

Cloudflare and browsers cache CSS, JS and images, so the server stamps every `css/`, `js/` and `images/` URL in a page with `?v=<version of those folders>` (`assetVersion()` in `server/index.js`) and caches requests carrying the current version for a year. In production (`NODE_ENV=production`, set in the Dockerfile) the version is a content hash taken once at startup; in development it follows file edits, so a reload shows changes without restarting the server. Scripts that load files themselves reuse the stamp from their own URL (see `VERSION` in `chat.js`). Pushes to `main` deploy automatically: a GitHub webhook calls Coolify, which rebuilds the Docker image.

## Architecture

- **Content lives in `js/data.js`** as global consts: `SITE` (contact info, donate and social links, `checkoutEndpoint`, `formsEndpoint`), `CATEGORIES`, `AREAS`, `MEMBERS`, `EVENTS`, `GALLERY`, `VIDEOS`, `PARTNERS` (Gold and Platinum sponsors for the home page), `LEADERS`, `REGISTRATION_FEE`, `TIERS`. Editing site content means editing this file, not the HTML.
- **Draft mode**: while `SAMPLE_DATA` is true, `main.js` adds `.is-draft` to `<html>`, which shows the dashed `.draft-note` elements (static in the HTML) and keeps empty sections visible. With it false, notes hide, sample `LEADERS` are dropped, and any section whose list is empty gets `data-empty` and is hidden (gallery, videos, leaders, partners). Links set to `"#"` (`SITE.donate`, social URLs, member `url`) are never rendered.
- **`js/main.js`** (single IIFE, loaded after `data.js` on every page) does all rendering:
  - Injects the shared header/footer by replacing the empty `#site-header` / `#site-footer` placeholders. Nav links are in its `NAV` array; the active link comes from `location.pathname`. To add a page, update `NAV` and copy an existing page's `<head>` and script tags.
  - Renders data into elements by id, each guarded by an existence check: `#home-events`, `#events-list`, `#home-dir`, `#dir-grid` (with `#q`, `#cat`, `#area`, `#chips`, `#count`; `#q` is pre-filled from `?q=`, which the home page's member search submits), `#gallery` (optional `data-limit`, native `<dialog>` viewer), `#videos` (every entry in `VIDEOS`: YouTube through youtube-nocookie, Instagram reels through Instagram's official embed, whose script loads only when a reel nears the viewport; any `<div data-video="key">` shows one video by itself, as on the About page), `#partners`, `#leaders`, `#tier-list`, `#hero-signup`.
  - Email signup: on home it renders an email-only form into `#hero-signup`, inside the gold newsletter section after contact. Every other page except `membership-success.html` gets the signup band (`#newsletter`, email + zip) appended above the footer instead. The forms endpoint accepts newsletter email without ZIP, and validates ZIP when supplied.
  - User-facing strings from data go through `esc()`. Keep that when adding renderers.
- **Forms**: the newsletter, contact and chat-question forms POST urlencoded data with a `form-name` field to `/api/forms`. `server/forms.js` keeps only the fields listed for that form in `FORMS` (adding a field means adding it there), validates them, appends one JSON line per submission to `$DATA_DIR/submissions.jsonl`, and posts it to `FORMS_WEBHOOK_URL` if set. Staff download everything as CSV from `/admin/submissions.csv` (Basic auth, password = `ADMIN_TOKEN`; `?form=newsletter` filters). All forms use a `website` honeypot field, and the server rate-limits posts per visitor.
- **Membership checkout**: the `#tier-list` radios are step 1 of `#join-form`, grouped by each tier's `group` and showing its `fit` tag and `blurb` (wording taken from the client's live membership page), plus an `includes` list (`includesFrom` renders "Everything in X, plus:"). The current `includes` lists are a proposal the chamber hasn't approved: `includesDraft: true` shows them with a "Draft" label only while `SAMPLE_DATA` is true, and hides them otherwise. Flip it to false per tier once the chamber confirms that tier's list. A tier with `guardian: true` (Youngpreneur, ages 15 and under) reveals `#guardian-note` in step 2. Keep that note: the form collects contact details, and COPPA requires parental consent for children under 13. Submitting POSTs JSON to `/api/checkout` (`server/checkout.js`), which builds a Stripe Checkout session with the membership and the $25 registration fee as separate line items and stores the member's answers as metadata. **Tier ids, names and prices exist twice**: `TIERS` in `data.js` (display) and `TIERS` in `server/checkout.js` (what Stripe charges and the receipt shows). Keep them in sync. Needs `STRIPE_SECRET_KEY` and `SITE_URL` (the public https address, used for Stripe's return links).
- **Chat assistant**: `js/qa.js` is the Q&A knowledge base (`ASSISTANT` texts, `QA`, `FALLBACK`, `SYSTEM_PROMPT` for any future AI model); `js/chat.js` matches questions by keyword overlap against it, ignoring a stop-word list, and offers to send unanswered questions (with an optional reply email) to the team through `/api/forms` as the `question` form. QA entries with `form: "newsletter"` show an email + zip sign-up in the chat, saved as a `newsletter` submission whose `page` ends in `(chat)`, so staff can see which leads the assistant brought in.
- **The chat's Sankofa bird**: the chat launcher is the client's Sankofa bird art (`images/sankofa-mascot.webp`), animated by a React + Motion component in `mascot/` (see `mascot/README.md`). `npm run build:embed` in `mascot/` compiles it into **`js/sankofa-mascot.js`**, a committed build output (about 100 KB gzipped) that defines `window.SankofaMascot`; never edit it by hand, and rebuild it after changing `mascot/src/`. `chat.js` loads that file after the page, mounts the bird as the launcher, and drives its states: `welcome` with the greeting, `listening` while the question box has focus, `thinking` for 650 ms before each answer, `speaking` while it shows, `happy` after a sign-up, a sent question or a thank-you. If the file is slow (2.5 s), fails, or the visitor has Save-Data on, `chat.js` shows the plain "Ask us" button with the same art instead. Once per visit (a `sessionStorage` flag) a speech bubble (`ASSISTANT.hello`) greets 4 seconds after a page loads; each option opens the chat and asks it. On every later page the bird thinks for a moment, then says one of that page's five `PAGE_TIPS` (end of `qa.js`), picked at random, with a button that asks the chat a related question or links somewhere on the page; picking one starts the chat with the tip. Tips show once per page per visit, four per visit at most, and stop for the visit after two bubbles in a row are closed. Bubbles are skipped on `membership-success.html`, while the chat is open, and while someone is typing in a form. When editing tips, keep them true to the page and check each `ask` still gets the intended answer. A few tips are built from `data.js` (cheapest tier, registration fee, next event) and drop out when that data is empty. To change the art, replace `mascot/assets/sankofa-source.webp` and run `npm run image`.
- **Motion**: keep the Sankofa bird as the homepage's distinctive animated element. Lists marked `data-reveal="stagger"` on other pages animate in with the Web Animations API, only when they start below the fold. Content is never hidden by default, and motion respects `prefers-reduced-motion`.

## Design system (`css/styles.css`)

- The palette is the four colors the client named: gold, blue, teal and sepia brown, all sampled from the chamber emblem and used at full strength, as OKLCH tokens in `:root`. Blue is the `--navy-*` scale (`--navy-800` is the emblem's #232856) and sepia brown is `--sepia-*` (`--sepia-700` is the Sankofa bird's #633b13). Don't introduce other hues; an earlier orange was removed for this reason. The client asked to keep these colors for cultural representation, and found an earlier, mostly white version too "news-like": the site should pop with color like their original. Gold (`--gold-*`, with `--gold-600`, the emblem's own gold, as hover and gradient end) carries buttons and sunrise grounds; blue, teal and sepia carry the color bands and blocks. Haint blue (`--haint-*`, the pale blue-green of Lowcountry porch ceilings) and `--teal-100` are the light tints.
- Contrast is checked against WCAG AA: text on gold, `--teal-500`, `--teal-300` and `--sepia-500` is navy; text on `--teal-700`/`--teal-800`, navy and `--sepia-700` is white (titles may use `--gold-300`). Never put gold, `--sepia-500` or `--teal-500` text on white; use `--sepia-700` or `--teal-700` for colored text. `--sepia-700` barely separates from navy (1.4:1), so color blocks on navy grounds use `--sepia-500`.
- Grounds: `.on-navy`, `.on-gold`, `.on-teal`, `.on-haint`, `.on-haint-soft`; interior pages pick a header band with `.page-head` (teal), `.page-head.navy`, `.page-head.sepia` (About) or `.page-head.sun`. Each re-sets `--focus` and link colors.
- Type: League Spartan (display) + Lato (body), the fonts of the chamber's original site, loaded from Google Fonts in each page's `<head>`. Emphasis inside headings (`<em>`) is a color change, not italics; League Spartan has no italic.
- The client prefers the original website's format and flow. Home follows introduction → mission → four pillars → work and membership → community served → contact → newsletter. Preserve this story order and the broad image/text sections; do not reintroduce an early signup bar, service-card grid, audience chips or empty proof sections. Directory and events remain on their own pages with useful contact paths until real listings are supplied.
- The `.chamber-*` classes are the revised homepage. The three `images/home-*.webp` assets reuse published original-site imagery; `images/home-image-sources.json` records their sources. Do not identify pictured people or present the images as verified event photographs. Mobile places hero copy beneath its image and follows DOM reading order throughout.
- Shared navigation uses native `<details class="nav-about">` for About, leadership and heritage; the submenu sits in normal flow on mobile. `SITE` remains authoritative for phone/address/donation links and is bound into homepage elements with `data-site-*` attributes. Leadership names/roles come from the chamber's published leadership page; keep fictional businesses/events out of client-facing data.
- Section kickers (small uppercase labels above headings) and numbered markers are deliberately avoided, except that one hero badge and the real 1-2-3 steps of the membership form.
- Brand assets in `images/`: `emblem-*.webp` (Sankofa shield, opaque white background, so it sits on white surfaces with `mix-blend-mode: multiply`), `crest-*.webp` (round seal, shown with `clip-path: circle()` to drop its cream corners), favicons cut from the crest, and `rays.svg` (the emblem's sunburst, used as a CSS mask so CSS sets its color).
